## 2024-08-02 - Offloading I/O ContentResolver operations from Jetpack Compose rendering
**Learning:** During my exploration, I saw that the `PDFDecryptorScreen` composable function in `MainActivity.kt` executed `getFileName` to fetch file display names synchronously inside the `@Composable` tree. `getFileName` invokes `context.contentResolver.query(uri, null, null, null, null)`, which hits a system provider. Running I/O queries directly within the Compose render path can cause UI stutter/jank (main thread blockage) as recompositions trigger re-evaluations, which violates Android app responsiveness patterns.
**Action:** Utilize a `LaunchedEffect` hooked to `selectedUris` to suspend and offload the querying string building to `Dispatchers.IO`, saving it to a single `selectedFileNames` string state.
